# NEMT 实证实验标准流程

本流程是策略研究的默认路径。它的目标不是制造更高胜率，而是回答一个可证伪的问题：某个新增模块在冻结条件下，是否带来独立、可实现、不过度依赖极少数幸运样本的收益增量。

## 1. 预注册与冻结

实验运行前必须写明：

1. 单一研究问题、零假设与备择假设；
2. 基线、实验臂和唯一允许变化的变量；
3. 数据市场、时间范围、时区、成本、资金费率与缺失值规则；
4. 入场、退出、保护止损、风险预算和组合并发约束；
5. 主要指标、尾部利润指标、拒绝条件和晋级条件；
6. 样本内、验证集与最终时间留出集的边界；
7. 配置、代码、输入数据和依赖版本的指纹。

冻结后不得因结果不好而修改主判据。任何事后分析必须标记为 `EXPLORATORY`，并进入下一份预注册，而不是回写本次假设。

## 2. 因果执行与安全边界

- 只使用在决策时已经完成的 K 线和当时可得数据，禁止未来函数。
- 手续费、滑点、资金费率、最小名义金额和成交约束必须进入账本。
- 研究环境与实盘环境隔离；默认 `PAPER/RESEARCH`，订单数必须为零。
- 不读取或传输实盘交易凭证，不自动下单，不把模拟利润称为实盘收益。
- 云端运行应固定实例、容器/运行时、命令、开始结束时间和输出路径。

## 3. 最低审计账本

每笔交易至少保存：资产、方向、信号时间、入场/出场时间与价格、持有期、数量、原始与调整后仓位、手续费、滑点、资金费率、净收益、R、MFE、MAE、退出后路径和退出原因。

涉及状态层时，每根 K 线还应保存：相对成交量、成交量 Z-score、OBV/成交量趋势、Wyckoff 事件、NEMT entropy/psi/phase、原始仓位、各调整因子、最终仓位、硬门拒绝原因，以及被拒交易的反事实结果。

汇总结果必须能从交易账本重建；交易账本与逐 K 线账本必须提供 SHA-256。

## 4. 分析顺序

1. 对账：资金曲线、交易损益和成本是否一致；
2. 样本外：主要结论在冻结时间留出集是否同号；
3. 尾部：前 1/5/10 大赢家贡献及删除赢家后的结果；
4. 路径：MFE/MAE、持有期、退出后延续空间和恢复期；
5. 风险：最大回撤、止损簇、相关暴露和并发资金约束；
6. 消融：新增模块相对纯价格基线的独立增量；
7. 反事实：硬门删除了什么，软评分究竟区分了赢家还是仅放大总杠杆。

胜率不作为核心晋级条件。主要目标是样本外净利润、尾部捕获、可承受回撤和利润来源的稳健性。

## 5. 统计与图表

- MATLAB、Python 或 R 的分析脚本必须可重复运行，输出机器可读表格和图表。
- 报告至少包含基线/实验臂净利润、时间留出收益、回撤、尾部集中度、删除赢家测试、止损簇和仓位因子结果。
- 若多个参数或实验臂被比较，必须披露选择偏差；不得只发表最佳臂。
- “提高利润”不等于“产生信息增量”。应补做资本中性或同回撤比较，排除广义加杠杆解释。

## 6. 发布与审查

1. 用 Quarto 管理数据驱动正文，用 Typst/PDF 工具完成公式与版式；
2. 逐页检查 PDF，使用 EPUBCheck 校验 EPUB；可验证时再声明 PDF/A；
3. 发布冻结设计、结果 JSON、审计账本指纹、分析脚本、图表和正负结论；
4. 报告可发送到研究群，但必须附“历史研究、非交易许可”；
5. 通过 GitHub PR 接受人工评审，不因回测结果自动合并、部署或交易。

## 7. 决策标签

- `ADVANCE`：全部预注册门槛通过，可以进入下一轮独立复现；
- `REJECT`：任一硬门失败，保留负结果；
- `INCONCLUSIVE`：数据或识别能力不足，不能声称支持或否定；
- `BLOCKED`：数据、执行或审计前置条件不满足。

只有独立复现、真实组合约束和前向 PAPER 观察都通过后，才允许讨论部署候选；这仍不等于授权实盘。
