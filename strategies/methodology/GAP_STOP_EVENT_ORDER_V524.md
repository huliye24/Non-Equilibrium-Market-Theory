## 1. 两个可明确指出的模型缺陷

源实现：[Emergenzix 的 v5.2 历史模拟](https://github.com/huliye24/emergenzix/blob/d6962bedb9cf18e927ac9ae768e55eb4a57ea0d9/backend/emergenzix_api/nemt_strategy/v52_turtle_cli.py)。

**缺陷 A：开盘不利越价没有进入止损价格模型。** 对既有仓位，源代码只要当根 `low <= stop`（多头）或 `high >= stop`（空头）便使用 `raw_exit = stop`，未区分当根开盘已经低于多头止损价或高于空头止损价的情形。这种建模对不利跳跃的损失可能过度乐观。

**缺陷 B：整根 K 线的极值可能覆盖先于它发生的通道退出。** 源代码先检查当根 `high/low` 是否触止损；即使上一根已确认 K 线已经触发“下一根开盘退出”的通道指令，仍以 `stop_hit` 优先，可能使用开盘之后的止损事件取代本应在开盘发生的退出。

这些是**代码静态审阅得到的语义不一致**，不是对 2025 年全部成交、真实交易所订单簿或累计 PnL 已作重算的断言。BTC 24/7 市场不等于永远连续成交：K 线开盘可能跨越止损价，OHLC 不包含队列、滑点和完整盘口。

## 2. 精确定义

用 `t` 表示正被回放的完整 4h K 线；`O_t,H_t,L_t,C_t` 是该根 OHLC，所有开盘前允许的决策只能用至 `t-1` 已确认信息。令 `d=+1` 为多头，`d=-1` 为空头；`P` 是从此前持仓状态继承且在 `t` 开盘前已有效的保护止损价。

上一步 v5.2.3 的**新开仓即生效保护**依旧成立。此处主要讨论前一根已经持有仓位的情形。

```text
gap_breach(t, d, P) =
    (d == +1 and O_t <= P) or
    (d == -1 and O_t >= P)

intrabar_stop_touch(t, d, P) =
    (d == +1 and L_t <= P) or
    (d == -1 and H_t >= P)

channel_exit_pending(t) =
    仅由截至 t-1 已完成 K 线产生、计划在 t 开盘执行的退出请求

adverse_exit_slippage s >= 0:
    modeled_exit_price(raw, d) = raw × (1 - d × s)
```

### 仅供历史研究的止损成交参考价

```text
if gap_breach:
    stop_reference = O_t        # LONG 开盘低于止损 / SHORT 开盘高于止损
else if intrabar_stop_touch:
    stop_reference = P          # 价格触及保护价的理想连续成交基线
else:
    no_stop
```

因此，作为不利方向的**保守开盘代理**，多头 `stop_reference = min(P, O_t)`，空头 `stop_reference = max(P, O_t)`，但该表达式**只在 stop 已经触发时**使用；不能在止损未触发时强行成交。它仍非真实成交保证：当根内部跳价或流动性断层可能使实际成交比 `P` 或 `O_t` 更差。

`s=0.0002`（单边 2 bps）与 `fee=0.0005`（单边 5 bps）仅作为**现有研究基线**沿用。必须在结果中分别披露入场费、出场费和滑点，不将 1% 事前止损风险预算解释为不可突破的实际亏损上限。

## 3. 对已有持仓冻结的事件顺序

在任何查看 `H_t/L_t` 的事后回顾前，先判断 `O_t` 与开盘应执行的订单：

| 优先级 | 条件 | 事件分类 | 研究价格参考 |
| --- | --- | --- | --- |
| 1 | 开盘已不利越过止损价 | `STOP_GAP_AT_OPEN` | `O_t` + 不利滑点 |
| 2 | 未越价，但上一根已产生通道退出 | `CHANNEL_EXIT_AT_OPEN` | `O_t` + 不利滑点 |
| 3 | 上两项均未发生，但当根随后触及止损 | `STOP_TOUCH_INTRABAR` | `P` + 不利滑点（理想基线） |
| 4 | 均未发生 | `HOLD` | 继续以期末价格估值 |

- 当 `gap_breach` 与通道退出同时在开盘有效时，保守报告 `STOP_GAP_AT_OPEN` 并记录 `channel_exit_pending=true`；两种订单以同一 `O_t` 作为价格代理，**不声称能从 OHLC 判定真实订单先后**。
- 若先前通道退出应于开盘执行且开盘没有越过止损价，则该仓位在 `O_t` 已结束；即使随后 `L_t` 或 `H_t` 达到原止损价，也**不能倒算为该仓位的止损**。
- 新仓位若于当前 `O_t` 开立，必须依 v5.2.3 在同一根 K 线内检查其**新建**止损；不可使用开仓前本就存在的旧仓位事件。平仓后是否允许同一开盘再建新仓不在本次改动范围，应保留既有策略规则、单独审查潜在重复交易。
- 无效 OHLC、错序 K 线、止损价不合法、无法复核的市场状态应标为 `BLOCKED/INCONCLUSIVE`，不能静默假定以理想价格成交。

## 4. 合成反例（不是 BTC 历史数据）

| 场景 | 持仓 | 既有止损 `P` | 当前 `O,H,L,C` | 通道退出待执行？ | 应归类及参考价 |
| --- | --- | ---: | --- | --- | --- |
| 开盘下跳 | LONG | 98 | 95, 99, 94, 96 | 否 | `STOP_GAP_AT_OPEN`，95 |
| 开盘上跳 | SHORT | 102 | 106, 107, 99, 101 | 否 | `STOP_GAP_AT_OPEN`，106 |
| 正常触价 | LONG | 98 | 100, 102, 97, 101 | 否 | `STOP_TOUCH_INTRABAR`，98 |
| 先于跌价退出 | LONG | 98 | 101, 102, 96, 99 | 是 | `CHANNEL_EXIT_AT_OPEN`，101 |
| 同时开盘越价并预定退出 | SHORT | 102 | 105, 108, 101, 104 | 是 | `STOP_GAP_AT_OPEN`，105，另记同时退出请求 |

以上参考价均为**未扣除滑点与费用的原始价格**。原 v5.2 的 2025 交易成绩不因这些假想例子自动变化。

## 5. 对研究证据的限制与未来验收

1. **本 PR 不修改任何交易程序**。由 Emergenzix 将该优先级作为独立的回测诊断任务实施，记录实现提交、数据版本/sha256 和成本参数。
2. 对同一 2025 年历史区间报告 `STOP_GAP_AT_OPEN`、`STOP_TOUCH_INTRABAR`、`CHANNEL_EXIT_AT_OPEN` 的笔数、逐笔价格差额、费用、净 R、回撤；将止损与通道同时触发的开盘情况单独列出。
3. 必须与 v5.2.3 的**开仓同根触发**分别归因；若同时修复，必须分阶段保存对照与证据，不能把累计收益变化归因于单一改动。
4. 原始 `v5.2` 2025 年 -6.3321% 历史成绩**保留不可覆盖**；2025 已经用于策略开发，新的复测属于探索性诊断，不得再次当作未见样本外验证。
5. 实盘止损市场单不保证触价成交。若缺少逐笔交易或盘口重放，必须同时报告模型依赖和极端滑点/成交失败限制，不能认定上述代理完全捕捉交易所风险。
6. 未完成独立审查的 v5.2.x 系列继续为研究状态，**不具备 PAPER/LIVE 晋级资格或 Telegram 开单信号资格**。

**本步结论**：先确保价格模型与事件时间顺序具有可检验的定义，再研究收益变化；不是假设更复杂的止损一定提高盈利。
