## 1. 为什么需要单独检验 NEMT，而不是继续优化交易参数？

[Emergenzix v5.2 当前实现](https://github.com/huliye24/emergenzix/blob/d6962bedb9cf18e927ac9ae768e55eb4a57ea0d9/backend/emergenzix_api/nemt_strategy/v52_turtle_cli.py) 要求 **NEMT 临界方向** 与 **20/55 日 Donchian 突破方向** 一致才允许进场。两者都从已完成价格序列计算，因而存在强重叠信息的可能。

[2025 年保留的原始研究报告](https://github.com/huliye24/emergenzix/blob/d6962bedb9cf18e927ac9ae768e55eb4a57ea0d9/docs/reports/NEMT_V52_CONTINUOUS_2025.json) 记录 `nemt_directional_events=191`、`accepted_breakouts=18`、18 笔成交、总收益约 -6.33%。`candidate_audit` 只在 NEMT 产生方向状态时写入，**并不枚举所有 Donchian 突破事件**；因此现有数据没有“Donchian 单独策略”反事实，不能证明 NEMT 有增量价值，也不能依据 18/191 推断它筛掉了多少独立突破。

## 2. 数学对象和固定的信号时点

对每根已完成的 UTC 4 小时 K 线 `t`，先从与持仓状态**无关**的完整行情序列构建公共突破机会集合 `B`：

```text
Upper_120(t) = max(H[t-120], ..., H[t-1])
Lower_120(t) = min(L[t-120], ..., L[t-1])

B_t = +1   if C_t > Upper_120(t)
    = -1   if C_t < Lower_120(t)
    =  0   otherwise
```

严格大于、小于，不含等号；信号只能在 `t` 收盘确认。要求至少与旧 v5.2 同样的 330 根预热和完整 OHLC，缺口和未完成 K 线标记 `UNAVAILABLE`。

NEMT 按 [同一实现快照](https://github.com/huliye24/emergenzix/blob/d6962bedb9cf18e927ac9ae768e55eb4a57ea0d9/backend/emergenzix_api/nemt_strategy/nemt_momentum_v2.py) 冻结，不另设新阈值：

```text
NEMT_t = +1 if (S_t > 0.7) and (psi_t > +0.5)
       = -1 if (S_t > 0.7) and (psi_t < -0.5)
       =  0 otherwise

psi_t = 100 × EMA_alpha=0.3(simple returns from trailing 120 closes)
S_t = normalized Shannon entropy of 10-bin histogram of trailing 120 closes

G_t = 1 if B_t != 0 and NEMT_t == B_t else 0
```

这里 `EMA` 的首项为截取窗口内第一个简单收益，`S` 的分箱使用该窗口价格极值、10 个等宽箱；其定义是**历史实现的冻结口径**，不是在本实验中重新证明“熵等于市场相变”。`ψ` 与突破指标都含价格动量信息，因此即使 `G` 有效，也**不能直接证明它提供独立于一般动量的独特物理信息**。

| 费用/滑点 | 每侧 5 bps / 2 bps 基线 | 完全一致 |
| 订单与风控事件 | 收盘 `t` 决策，`t+1` 开盘基线；v5.2.3/.4 事件时序 | 完全一致 |

## 4. 核心估计目标与两层评价

### 第一层：共同候选事件上的筛选信息（主要理论检验）

从 **全部 20 日突破时点**（包含 `G_t=0` 的突破）记录候选；每个候选都用**相同**的独立虚拟单笔入场/退出、成本和止损模型计算事后净风险单位结果 `R_i^{net}`，不因 B 拒绝进场就丢弃其反事实标签。

预先定义：

```text
Delta_R = mean(R_net | B != 0, G = 1)
          - mean(R_net | B != 0, G = 0)
```

- `H0: Delta_R <= 0`：NEMT 许可未显示正的选择增量；
- `H1: Delta_R > 0`：获许可事件的成本后风险单位结果高于被拒绝事件；
- **只有两组均有足够且可审计的事件时才估计 `Delta_R`**；一组为零、样本过小或时间覆盖不足时报告 `INCONCLUSIVE` 而不是填零。
- `R_i^{net}` 以该虚拟交易的**计划初始止损风险** `quantity × D` 为分母（必须大于零），以扣除双方手续费、滑点以及已定义跳空模型后的实际净 PnL 为分子。固定评价期末仍未退出的候选须注明 `CENSORED`，不擅自当作完整赢家或输家。
- 同一价格趋势中相邻 K 线信号会高度相关。保留全部事件原始计数，并按此前 v5 研究已声明的**同方向间隔至少 12 根 4 小时 K 线**规则构建一组首次事件的去重诊断（按时间选择首个，禁止根据事后收益挑选）；时间块自助法/不确定性估计必须以趋势事件或时间段为簇，不得视作独立同分布交易。
- 需另报 `mean(R_net | G=1)` 是否本身为正、方向分组、多空分布、事件数及置信区间。即便 `Delta_R>0`，若两组期望均为负，依旧不支持交易许可。
- **该条件差异是观察性筛选关联，不是 NEMT 临界机制的因果证明**；动量、波动率、趋势成熟度以及时间状态可能同时影响 NEMT 判定和未来结果。

### 第二层：完整单账户策略（应用效果，次要）

在相同样本上分别用 A/B 独立、互不共享的虚拟单账户账本运行；完整报告成本后总收益、最大回撤、交易数、风险暴露时长、风险单位收益、方向占比、交易费用、期末未平仓结算方式。

**必须披露共同突破全集 vs 可持仓实际入场集合的区别**：当 A 已有仓位而 B 为空仓时，后续可执行机会可能不同；因此组合 PnL 差异受到交易机会路径、暴露时长和持仓互斥的影响，不能简单等同 `Delta_R`。增加每单位在市时间/每单位风险暴露表现，仅作描述，不以随意缩放杠杆强行配平组合。

## 5. 失败标准、证据完整性与污染控制

1. **2025 年研究期已经被多次观察和选择策略**，对其重算只能作为 `EXPLORATORY` 诊断；不可重新贴 `OOS` / `REPLICATED` 标签。
2. 在开展任何新的确认性数据评估前，需独立补充不可变的**市场、开始与结束、随访区间、数据 SHA-256、实现提交、时间戳协议、交易成本、唯一事件去重/删失规则、主要 `Delta_R` 统计方法、置信区间与判断阈值**。本文件在这些事项冻结前的状态为 `PROTOCOL_DRAFT`，不是完成的预注册。
3. 必须枚举所有 Donchian 候选，并同时计算 NEMT 状态；旧报告仅记录 NEMT 定向事件，不能直接从原 `candidate_audit` 重构本实验。
4. 在使用任何历史收益前，先用合成 4 小时 K 线核对：突破但 NEMT 不许可、突破且许可、无突破但 NEMT 临界、临界方向相反、窗口不足、同根止损及跳空事件。异常应 `BLOCKED`。
5. 如果 A/B 均无正的保守净期望，或筛选后的风险不合理，允许结论为 **NEMT 许可没有足够的交易证据**，不因团队需要一个成功策略而放宽门槛。
6. 不得在看过结果后调整 `psi`、熵阈值、EMA 权重、120/60 通道、ATR、2N 或临界定义。欲检验“是否超过简单动量筛选器”，需以**独立预注册的新对照**另行设实验臂，并避免使用本轮测试区间调参。
